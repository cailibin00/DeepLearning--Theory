## 大模型的内存开销
首先我们来学习一下基本的内存知识。

- 训练：
`总内存 = 参数值 + 梯度 + 前向传播激活值 + 优化器状态 + 临时缓冲区`
- 推理：
`总内存 = 参数值 + 临时缓冲区 + 前向传播激活值`


### 参数值
和模型的参数数量有关，还和参数的精度有关，如果FP32那么x4，FP16则x2

$$占用内存 = 参数量 * 参数精度 / 1e9$$
### 梯度
占用内存和参数一样，精度也一样


### 前向传播激活值
也就是模型所有层的所有输出，是用来反向传播之后计算梯度使用的。

是根据模型的架构计算的。和batch size ， sequence length相关。

### 优化器状态

| 优化器               | 状态/参数 | 总倍数 | 说明      |
| ----------------- | ----- | --- | ------- |
| SGD               | 0×    | 1×  | 只有参数本身  |
| SGD with Momentum | 1×    | 2×  | 保存动量    |
| Adam              | 2×    | 3×  | 一阶矩和二阶矩 |
| AdamW             | 2×    | 3×  | 同Adam   |
| Adagrad           | 1×    | 2×  | 梯度平方累积  |

### 临时缓冲区
通讯缓冲区、中间计算结果。

### MapReduce
![MapReduce示意图|600](file-20251103150404046.png)
- 这里使用文本的计数这个场景来讲解
1. Input：用户输入的文本，有很多行
2. Split：用户输入的文本按照不同的行切分成不同的部分
3. Map：一个部分对应一个 **Mapper/worker** ，计算一个单词出现的次数（分而治之思想）
4. Shuffle：取Mapper的结果，挑选不同的单词进入不同的**新的worker**（分而治之思想）
5. Reduce：**整合拼接**Worker的结果
6. Finalize：输出得到最终结果

![示例图2|600](file-20251103150948228.png)
- 这里使用文本索引的例子，读者可以根据上述思路
1. Input
2. Split
3. Map
4. Shuffle
5. Reduce
6. Finalize

- 总结MapReduce框架
首先，我们有用户进程，它需要协调或者定义我们程序怎么运行，它会先想数据有多少，需要拆解成多少个Mapper，多少个Reducer去做。比如要找5个Mapper去做，就会把数据拆成5份，这样会产生出很多很多Worker，会有Map Worker和Reduce Worker。

但最重要的是还会产生一个**Master Worker**，这个和其他Worker等级是一样的，只不过会做一些特殊事情，它会作为用户的代理来协调整个过程，用户就可以做其他事情。Master Worker会让这个Worker去拿0号数据，一个Worker负责拿1号数据等等，这就是分配数据的过程。

每个Worker会在本地把数据切分开吧，写到本地的缓存或者硬盘上行。前面Map Worker做完了，Master让Reduce Worker去拿数据，他们就会从各个Worker里拿到本地需要的数据，在本地做完Reduce以后将结果写到最终的文件里就是Finalize。实际上，这个过程可以看到第一步切数据是Input，第二步是Map拿数据Split，第三步自己切分就是Map，第四步Reduce去拿数据是Shuffle，第五步Reducer自己去做数据的整合是Reduce，第六步输出结果Finalize。

## Data Parallelism
分为两个类别，Ring All-Reduce 和 Parameter Server，这都和分布式通信原语密切相关。

作为第一个概念，我们介绍一些简单的东西

$$time = 数据规模 * 单步计算量 / 计算速度$$
$$计算速度 = 单设备计算速率 * 设备数 * 多设备并行效率$$
- 其中，设备数并不是越多越好，还和数据的规模，还有服务器的架构有关。

在Data Parallelism之中，需要解决的问题是不同batch在多卡上计算的梯度汇集问题，我们假设第一个GPU是服务器。
### Ring All-Reduce
我们说着很容易，reduce scatter，all to all，但是要高效实行是需要严格的算法的。

- Ring：首先要明白，这个模型之中GPU是线性连接成一个环的。每一个GPU有一个从下一个GPU的输出接口，从上一个GPU的输入输入接口。
- All-Reduce：该算法只需要执行两次循环，就可以完成**All Reduce**的操作

- 感性理解：因此，随着GPU数量增加（例如一个），样本数量增加（卡越多能够处理的样本越多），但是完成通讯只需要线性增多（每个GPU增多1x2次）。并且，在这样的安排下，**每个设备的入口带宽和出口带宽都被用上了**，而且不会发生争抢带宽的事情。
- 定量分析：假设带宽为β，总样本数为V，GPU数量为p
$$time = \frac{V(p-1)}{p\beta}$$
$$data\_each\_gpu = \frac{V(p-1)}{p}$$
