
## 范式
### CoT
早期的思维链（Chain-of-Thought, CoT）虽然提升了模型在逻辑任务上的表现，但其本质仍是**线性**的、一次性的生成过程

### ReAct
- **运行机制**： ReAct打破了LLM“输入-输出”的黑盒模式，强制模型遵循Thought（思考）→ Action（行动）→ Observation（观察）的循环。
1. Thought： Agent首先生成一段自然语言的内心独白，分析当前状态，识别缺失信息，并规划下一步行动。例如，“用户询问了三家公司的股价对比，我需要先分别查询这三家公司的当前股价。”
2. Action： 基于思考的结果，Agent生成特定的指令来调用外部工具（如搜索API或Python解释器）。
3. Observation： 外部工具执行指令后，将结果（如“APPL: $150, MSFT: $280”）作为新的上下文反馈给模型。
4. Loop： 模型基于新的观察结果，进入下一轮Thought，直到任务完成 。   

- **局限性分析（线性机制）**： 尽管ReAct在许多基准测试中优于零样本提示，但其固有的线性特征导致了严重的**错误传播（Error Propagation）** 问题。一旦Agent在初期的Thought步骤中产生了幻觉或逻辑谬误（例如选择了错误的搜索关键词），后续的Action和Observation将基于错误的假设继续执行，导致整个任务轨迹偏离目标。ReAct缺乏内建的“**回溯**”机制，无法在发现死胡同后自动返回上一步重试 。


综合分析，ReAct帮助模型可解释性的拆解问题，调用外部搜索来获得知识，同时，不断反馈来获得新的知识。但是，还是离不开线性，也就是没办法有一个自我批判机制。


### Reflexion
核心思想 ： **推断时的计算（Inference-time Compute）** 可以替代训练时的计算

ReFlexion利用强化学习的思想，在不更新参数的基础上，优化了模型的输出。

- Actor：就是接受用户的输入，生成内容的。利用强化学习的理解，就是输出一个轨迹
- Critic：对模型的输出打分
- **Self-Reflexion**：在强化学习中，这一步是计算损失函数，反向传播优化参数；在这里我们利用大模型生成一段反思文本，分析错误原因。
- Re-exe：利用错误的信息拼接作为新的输入，能够矫正在原有的采样上的失误策略，生成新的文本。

### ToT
既然CoT线性不行的，那么我们就选择多个方案来评估：
1. 生成多个回答
2. 利用广度优先搜索或者深度优先，来遍历路径
3. 使用critic来评价这条路径是否可以（如果不行，就剪枝）

核心就是：并行CoT + critic思想

ToT将LLM的推理过程建模为在树结构上的搜索。每个节点代表一个“思维状态”（Partial Solution），边代表思维的演进。

- 搜索策略： ToT允许使用广度优先搜索（BFS）或深度优先搜索（DFS）来探索解空间。
- 评估与剪枝： 关键在于引入了一个“评估器”（Voter/Critic）。在生成多个候选思维后，评估器会预判每个分支的前景。如果某个分支看似无法通向正确答案，Agent会主动剪枝（Pruning）并回溯（Backtracking）到父节点，尝试其他路径。这种“前瞻性”（Lookahead）和“全局决策”能力是CoT所不具备的 


### GoT
GoT强化了节点之间的控制：

GoT 的图不是一次性生成的，而是通过代码控制器 (Controller) 动态构建的。
构建过程包含几种基础的拓扑操作：
1. 聚合 (Aggregation) —— GoT 的杀手锏 ($N \rightarrow 1$)这是 ToT 做不到的事情。在 ToT 中，分支 A 和分支 B 是竞争关系（一个死，一个活）。但在 GoT 中，模型可以将多个分支的优点结合起来。逻辑：取“想法 A”的优点和“想法 B”的优点，合成一个更完美的“想法 C”.
2. 生成/转换 (Transformation/Generation) ($1 \rightarrow N$)这与 ToT 类似。基于一个思维节点，生成后续的一个或多个新节点。逻辑：基于当前思路，推导下一步。
3. 细化/循环 (Refinement/Looping) ($1 \rightarrow 1$)对同一个节点进行反复打磨。虽然在严格的 DAG 中不能有闭环，但在逻辑上体现为“自我修正”的迭代。逻辑：写一段话 -> 检查 -> 修改 -> 再检查。

并且，这种聚合是基于打分和语言输出的，就像是
A :xxxx  评价 + 打分
B :xxxx   评价+打分

使用一个 **控制器**，利用输出的指令聚合处理AandB的输出，类似于`A + B + "A的xxx很好，B的yyy很好，取其优点，生成一个新的方案"`
```python
merged_thought = llm.prompt(
f"参考以下两个想法的优点：\nIdea A: {best_thoughts[0]}\nIdea B: {best_thoughts[1]}\n生成一个更好的方案。"
        )
```

总结，允许不同方案的信息流动，是GoT的最大优点，但是也增大了开销。

### AoT
为了理解 AoT，我们必须看 ToT 有多麻烦：

- ToT 的工作模式（外部循环）：
1. Agent 生成 3 个想法。 -> 暂停，调用 LLM API。
2. 外部代码提取这 3 个想法。
3. Agent 评估这 3 个想法。 -> 暂停，调用 LLM API。
4. 外部代码决定保留哪一个，剪掉哪一个。
5. 循环上述步骤几十次。

缺点：网络交互次数多，延迟极高，Token 消耗巨大。

- AoT 的工作模式（内部循环）：
1. Prompt：“这是一个 24 点游戏。请使用深度优先搜索（DFS）算法来解决它。如果当前路径走不通，请回溯。请输出你的思考过程。”
2. Agent 一口气输出：“尝试 4+5=9... 走不通，回溯。尝试 10-6=4... 有希望，继续。下一步... 成功。”

优点：只需调用一次 API，速度极快。

总结：利用提示词调用，模型自己通过提示词实现“假ToT”解决办法

### LATS
集大成者：
1. 树
2. 打分
3. reflexion
4. ReAct搜索

- 改进：
1. 我们用树的时候，只会不断向前探索，可能会陷入类似于“局部最小值”。我们需要一个算法探索全局最佳
2. 我们用树的时候，只会在最高分的基础上往前走，但是所有的输出不一定存在好的值。需要引入反馈改进机制。
3. 我们使用树的时候，不能使用搜索。需要引入搜索引擎


- 流程：从用户输入开始
1. 生成节点：Agent 询问 LLM：“接下来可以采取哪些行动？”，LLM 生成 $N$ 个可能的动作（比如写出的 3 段不同代码，或者 3 个不同的网络搜索关键词）。这些动作成为树上的新叶子节点。
2. 评估/反馈：
	1. 执行：按照LLM生成的多个方案，执行方案（耗费很多时间）
	2. 得到反馈：例如代码报错，LLM输出，搜索引擎输入
	3. 反思+打分：使用LLM阅读，自己评估有什么不好的地方；打分，给后续选择路径使用
	4. 记录反思：将反思**记录在节点中**，后续调用的时候，推理路径上就不会出现这个问题。
3. 反向传播：更新分数。
4. 选择节点：它使用 UCB (Upper Confidence Bound) 公式来打分。$$U(s, a) = Q(s, a) + C \times \sqrt{\frac{\ln N(s)}{N(s, a)}}$$$Q(s, a)$：这个动作之前的平均得分（这条路好不好走）。后半部分：探索项（这条路是不是还没怎么走过）。直白解释：LATS 会优先选择那些**“之前表现好”或者“还没怎么尝试过”**的路径，避免一直死磕一个死胡同，也不错过潜在的机会。
5. 回到1
6. 结束条件：Condition A: 评估阶段发现结果**完全正确**（Solved）。Condition B: 达到**最大尝试次数**（例如 30 次迭代）或最大深度，此时选择分数最高的路径作为最终答案。

- 总结：利用的树的优点，同时**升级节点**为LLM输出+调用工具，在返回之后**优化节点**给节点加上反思记忆。


- 应用场景：**高精度，高难度**
LATS 是目前 HumanEval (代码生成评测) 和 WebShop (网络购物模拟) 等高难度榜单上的霸榜技术。
它证明了：让 AI 像人一样“三思而后行”（MCTS），并且“吃一堑长一智”（Reflection），是通往 AGI（通用人工智能）的重要路径。
虽然它速度慢、Token 消耗巨大，但在需要极高准确率和极高容错率的场景（如写医疗软件、金融分析、甚至控制机器人）中，LATS 是目前最可靠的架构方案。
