
## 流程

1. 意图识别 (Intent Detection)：模型分析用户的Prompt。如果用户问“今天新加坡天气怎么样？”，模型意识到自己内部数据（截止到训练时间）无法回答，需要外部数据。

2. 参数提取与格式化 (Argument Parsing)：模型根据**预定义**的工具描述（Schema），生成一段**结构化的文本**（通常是 JSON）。

```json
{
  "tool": "google_search",
  "parameters": {
    "query": "Singapore weather today"
  }
}
```
3. 外部执行 (Execution)：Agent 的运行框架（如 Python **脚本**）拦截到这段 JSON，暂停模型的生成，并在后台调用 Google Search API。
4. 结果回填 (Observation)：API 返回结果（例如“28°C, Rainy”），框架将这个结果**拼接**到对话历史中，再次喂给模型。

## 训练
模型并非天生懂 JSON 或 API，这主要依赖于后期的训练策略：

1. 有监督微调 (SFT - Supervised Fine-Tuning)
这是最关键的一步。开发者构建了大量 **“对话-工具调用”的数据集**来微调模型。通过这种训练，模型学会了将自然语言需求映射为**特定的 API 调用语法**。
2. 系统提示词 (System Prompting)
在推理阶段，我们会给模型一个很长的 System Prompt，告诉它有哪些工具可用。
3. RLHF (人类反馈强化学习)
为了提高准确率，还会使用强化学习。如果模型在需要搜索时却在瞎编（幻觉），或者调用的参数格式错误，就会受到惩罚；如果成功调用工具并解决了问题，就会得到奖励。
4. 核心思维框架：ReAct (Reasoning + Acting)
仅仅会调 API 是不够的，Agent 还需要懂得规划。这背后涉及到一个经典的 Prompt 框架：ReAct。

## ReAct举例
它要求模型在执行动作前先“思考”。模型会生成类似这样的内部独白：

- User: 现在的美国总统多大岁数？

- Model Thought (思考): 我需要先查现在的美国总统是谁，然后再查他的出生日期，最后计算年龄。
- Model Action (行动): search("current US president") 
- Observation (整合反馈): 结果显示是 Donald Trump (假设场景)。 

- Model Thought (思考): 知道了名字，现在查出生日期。
- Model Action (行动): search("Donald Trump birthday") 
- Observation (整合反馈): 1946年6月14日。 

- Model Thought (思考): 现在计算年龄。 
- Final Answer (最终回答): 他现在是 XX 岁。

ReAct 框架让模型能够处理多步复杂任务，而不仅仅是单次查询。
